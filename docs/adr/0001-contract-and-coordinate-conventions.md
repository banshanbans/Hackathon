# ADR 0001: Shared contract and coordinate conventions

- Status: accepted
- Date: 2026-07-16

## Context

SoloShot AI has an H5 client, an iOS client, and a Python API. Allowing each client to define its own session, issue codes, or coordinate system would make cross-device handoff unreliable.

## Decision

- OpenAPI 3.1 and JSON Schema 2020-12 under `packages/contracts/` are the cross-client source of truth.
- Public DTOs use `schema_version: "1.0"`.
- Normalized coordinates are in `[0,1]` with a top-left origin; x grows right and y grows down.
- Vision-native coordinates are converted at the iOS boundary before reaching shared domain models.
- Generated H5 and Swift types are committed and regenerated by `make generate`; they are never hand-edited.
- Write operations require an idempotency key, successful responses expose a request id, and errors use stable codes.

## Consequences

Contract changes must regenerate both clients and pass contract tests in the same change. iOS coordinate mapping must be centralized when Vision work begins in W4.
