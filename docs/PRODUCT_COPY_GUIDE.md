# SoloShot AI 产品文案规范

## 产品定位

SoloShot AI 是“AI 旅拍执行伙伴”。它帮助独自旅行者完成“看到灵感 → 理解画面 → 生成 ShotPlan → 现场拍摄 → 单点优化 → 完成作品”的完整旅拍过程。

界面不把 SoloShot 描述为摄影教程、姿势推荐工具、图片评分工具或开发能力展示页。文案先呈现用户想留下的画面，再说明当前要做的最小动作。

## 页面结构

每个主页面最多保留：

- 一个核心标题；
- 一句价值描述；
- 一个主要 CTA；
- 必要的状态、隐私或安全反馈。

避免重复标题、开发阶段 kicker、实现说明、技术链路说明和大段帮助文字。主要 CTA 使用结果导向表达，例如“生成我的 ShotPlan”“看看这一拍”“查看我的作品”。

## 保留词与创作方式

- 品牌名固定为 `SoloShot AI`；正文需要更简洁时可写 `SoloShot`。
- 产品能力名固定为 `ShotPlan`，不翻译为“拍摄方案”或“教程”。
- `original_replication` 统一展示为“原图复刻”。
- `scene_adaptation` 统一展示为“灵感迁移”。
- 两次拍摄统一展示为“第一次”和“调整后”，不展示 `Round` 或“第几轮”。
- `publish_readiness` 统一展示为“作品就绪度”，不展示“评分”或“发布准备度”。

## 可信状态

| 内部状态 | 用户界面 |
|---|---|
| `fixture` / `mock` | 演示模式 |
| `live` | 实时分析 |
| `cache` | 已恢复 |
| `fallback` | 稳妥模式 |
| `error` | 需要重试 |
| offline pending | 等待联网 |

演示模式必须明确说明结果来自精选或预设样例，不代表 AI 对用户本次照片的判断。实时分析必须在用户明确同意后才可发送素材。缓存、降级和错误状态不得伪装成实时结果。

## 展示值

ShotPlan 的原始枚举必须通过 H5 与 iOS 的类型安全映射后展示。例如：

- `waist` → “腰部高度”；
- `level` → “镜头水平”；
- `1x` → “1× 主摄”；
- `photo` → “拍照”；
- 未识别的姿势模板 → “专属构图”。

未知枚举不得直接回退为原始值。用户可执行的动作指令、安全提示和实时短指令仍来自既有可信来源，不在展示层自由生成。

## 禁用词

Release 用户界面不得出现以下开发或实现词：

- `Fixture`、`Live`、`Fallback`、`Round`、`Session`、`Provider`、`Vision`；
- `W2`、`W4`、`W5` 等工作包名称；
- Skill 名称、Plan ID、原始错误码、原始枚举；
- 幂等、冷启动、浏览器抽帧、像素压缩上限等实现说明。

这些词只允许出现在日志、Trace、测试名称和 `DEBUG Overlay`。产品错误提示通过稳定错误码映射成用户语言，原始错误码只写入日志或 Trace。

## 隐私、安全与演示真实性

隐私、授权、媒体保留时间、安全风险和演示真实性是必要信息，可以超出“一标题、一价值句、一主 CTA”的限制，但仍保持一句话完成说明。

外部 AI 同意文案固定为：“我同意将所选素材发送至火山方舟进行本次 AI 分析”。临时媒体说明固定为：“临时媒体仅用于本次任务，24 小时后自动清理。”

不得暗示面部身份识别、吸引力或身体评分，也不得把缓存、Fixture 或预录结果包装成实时 AI 判断。候选帧原因只描述清晰度、站位、人物比例、完整入镜和画面稳定性。
